# Task 1.1 - Critique
مشاكل الكود الإجرائي (order_system.cpp)
1. كل حاجة global
كل الـ arrays والعدادات فوق الملف متاحة لأي function. يعني أي حد يقدر يغير أي بيانات من أي مكان من غير ما يعدي على القواعد. لو حد كتب orderIsPaid[i] = true على طول، هيدفع order فاضي ومحدش هيمنعه، ولما البيانات تبوظ مش هتعرف مين اللي بوظها.

2. arrays
العميل الواحد مقسوم على 5 arrays (الاسم والإيميل والمدينة وغيرهم) ومربوطين ببعض بس بنفس الـ index. لو نسيت تحدّث array واحد، بيانات العملاء كلها تتلخبط. ولو عايز تضيف field جديد لازم تعدّل في أماكن كتير وتنسى واحد.

3. القواعد متفرقة ومتكررة
كل function بتتحقق من اللي يخصها بس، وفيه كود متكرر (زي 3 functions للبحث بالـ id نفس الشكل بالظبط). لو قاعدة اتغيرت لازم تلاقي كل مكان فيه وتعدله، ولو نسيت واحد النظام يبقى متناقض.

5. الـ Order مبيحفظش السعر والخصم وقت الشراء
الـ line بتخزن رقم المنتج والكمية بس، والإجمالي بيتحسب من السعر الحالي وحالة الـ VIP الحالية. لو سعر منتج اتغير أو عميل بقى VIP، إجمالي order قديم ومدفوع بيتغير لوحده، وإجمالي المبيعات بيبقى غلط.

6. Validation ناقص
التاريخ string عادي، فـ "hello" أو "2026-99-99" يتقبل.
السعر والـ stock ممكن يبقوا بالسالب.
الاسم والإيميل ممكن يبقوا فاضيين أو غلط.
لو كتبت حرف مكان رقم في cin، الـ stream بيبوظ ومحدش بيتعامل معاه.
7. الـ Stock بينقص من أول ما تضيف الـ line
حتى لو الـ order ما اتدفعش، والـ stock مفيش طريقة ترجّعه. لو حد عمل order وحط فيه كل الكيبوردات وما دفعش، المنتج يخلص وحد تاني مايعرفش يشتريه.

8. حدود ثابتة (MAX_*)
عميل رقم 51 أو order رقم 101 بيترفض، والحد ده جاي من حجم الـ array مش من قاعدة عمل. وكمان الـ array الـ 2D بتحجز مساحة للحد الأقصى حتى لو مش مستخدمة.

9. Index بدل reference
الـ order بيشاور على العميل والمنتج برقم مكانهم في الـ array. ده شغال بس لو الترتيب ماتغيرش. أول ما تضيف "حذف عميل" أو ترتيب، الـ orders كلها هتشاور على عملاء غلط.
